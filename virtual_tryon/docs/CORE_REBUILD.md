# 实时试衣核心重构判断（2026-10-26）

结论：需要替换试衣核心，不需要删除整个项目。“CatVTON 单帧 → 衣层分割 → 姿态 Warp”不能作为 Kivicube 类实时视频试衣的最终路线。现已接入默认的 FluxRT 完整帧生成原型：相机最新帧 → 5090 重新换衣 → 完整输出直显，无衣层提取或骨骼变形。它尚未通过真人运动及目标延迟验收，不能称重构目标完成。

## 已证实的问题

1. CatVTON 输出完整人物换衣照片；本项目随后把结果与输入区域、语义分割求交，再裁出衣层。这会裁掉衣物边缘、袖口和与模型重画头发重叠的区域。固定衣层依靠骨骼变形，不会为新的身体姿态重新生成褶皱、侧面和遮挡。
2. 页面原来默认 8 步；本地保存的官方 pipeline 默认 50 步、768×1024、CFG 2.5。8 步未经蒸馏的模型不能当作同质量的加速版。当前浏览器输入的 8/50 步对照中，50 步的绿色开襟和纽扣明显更接近参考，但图案和版型仍未完全恢复。
3. 旧的独立 benchmark 掩膜只有胸腹小块，遗漏了原衣摆和袖子。对它加到 50 步仍会保留未覆盖旧衣。该结果只能说明输入掩膜影响，不能当作真实浏览器掩膜的质量验收。
4. One Euro 对归一化坐标使用了过小的动态系数，快速动作下接近固定低通。192 px 位移的模块测试，14/18 Hz 输入跟到 90% 分别需 214/167 ms；校准后为 71/56 ms。静止合成噪声 RMS 由约 0.563 px 变为 0.571 px。这不是相机到显示器的总延迟。
5. 相机帧率、Warp 绘制帧率、真实生成帧率和人物动作延迟是四个指标。前两项通过不能证明衣服跟随或试衣质量通过；之前固定照片摄像头测试不足以验收真人运动。

## 本轮实际改动

- 页面新增“完整 AI 原图”：对照目标衣服、捕获人物帧和未经裁切的模型输出。即使后续衣层处理失败，完整图仍可查看。
- 页面默认改为 50 步质量基线，保留 8 步低步实验和 20 步均衡；当前仍是 512×768，不宣称已按官方全部配置复现。原 8 步测速数据作为历史速度对照保留。
- 旧版实时画面明确标为关键帧 Warp 实验；不再用相机流畅推导试衣实时合格。
- 校准归一化姿态滤波系数，并加入响应速度和静止抖动回归检查。

实际浏览器输入的 5090 对照：8 步推理 0.550 s、HTTP 2.826 s；50 步推理 2.732 s、HTTP 4.042 s。两次使用相同人物关键帧、服装、掩膜、512×768、CFG 2.5、seed 42；网络条件会变化。原始记录见 [core-audit-20261026.json](core-audit-20261026.json)。

## 建议保留与替换

保留摄像头采集、界面、衣物素材管理、Worker、状态接口、SSH 隧道和性能记录。CatVTON 降为静态换衣质量对照；旧衣层 Warp 保留为实验对照，停止作为最终实时路线持续补丁。

目标视频链路：

```text
摄像头 → WebRTC 视频上行 → 5090 参考衣服条件的流式生成
       ← WebRTC 输出视频 ← 完整生成帧
```

视频输出直接显示，避免再把生成结果裁成二维贴片贴回原画面。处理积压时丢旧帧，并记录输入/输出时间戳。目前使用二进制图片 WebSocket + SSH，尚未实现上述 WebRTC 传输。最新协议在一次上传得到服务端接收确认后即可采集下一帧，GPU只消费最新等待帧，回传与下次生成并行。可选 RIFE 平滑档发送三个整帧插值加一个完整模型原帧；页面分别报告显示与真实生成FPS，采样到绘制包括补帧缓冲。该更新减少卡顿，但未实现30FPS即时生成。

## 先验证一个独立小样

已在 5090 独立安装并实测 [FluxRT](https://github.com/tensorforger/FluxRT) + [FLUX.2-klein-4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B)，没有接回旧 Warp。两件参考衣物的静态完整输出，比本次 CatVTON 样例更能保留卡通图案、衣襟和织物；这只是有限样例的视觉判断，不是总体精度结论。

关闭插值后，512×512、2 步、空间缓存的平移照片序列约 4.05 个真实生成帧/秒；编译后中位耗时仍约 247 ms，未明显改善。576×320 编译档约 4.84 个真实生成帧/秒（中位 178 ms；总吞吐包含首个移动帧的停顿）。上述数据均不包含网络、视频编码和相机到屏幕延迟，输入也不是真人动作。因此 FluxRT 暂时只能作为质量更好的候选，不能宣布实时目标已达成。完整配置、冷启动和限制见 [MODEL_COMPARISON.md](MODEL_COMPARISON.md)。

官方 FluxRT 的 [benchmark](https://github.com/tensorforger/FluxRT/blob/main/benchmark.md) 使用 576×320、无参考衣服、4 倍插值；不能把其显示 FPS 当成本项目带衣服参考的独立生成 FPS。[LiveVVT](https://github.com/caoyushe/LiveVVT) 官方目前尚未发布可运行实现，不能直接替换部署。

小样通过后再接回现有前端：至少两件参考衣服、正面/半身、左右移动、抬手各一段连续视频；检查完整衣服、图案、袖口、遮挡和身份保持。同时分别测真实生成 FPS、插值显示 FPS、相机到输出延迟、网络 RTT。远程网络本身的延迟也必须计入。

如果开放模型不能通过上述验收，再比较 Kivicube 等服务的实际试用结果；是否接商业服务由用户另行决定。不能在仅看到论文或 README 跑分后承诺同等效果。
