# 摄像头实时虚拟试衣系统：技术方案选型

> 2026-10-26 复核结论：下面的关键帧衣层 + Warp 是历史原型，用户实际反馈显示其达不到目标实时试衣效果。新的试衣核心应先验证参考衣服条件的流式视频生成；当前代码尚未完成该重构。以 [CORE_REBUILD.md](CORE_REBUILD.md) 的判断和验收边界为准，不能继续把相机 FPS 当成衣服生成或运动跟随验收。

## 1. 结论

历史原型采用“**CatVTON 关键帧真实换衣 + 本地姿态驱动实时 Warp**”：

```text
摄像头实时流
  ├─ MediaPipe Pose Lite + Selfie Segmenter
  │    → One Euro / 掩码 EMA
  │    → 36×54 服装网格 Warp
  │    → WebGL 实时显示
  └─ 人体稳定入镜约 1 秒
       → 捕获人物帧、人体掩膜和姿态
       → CatVTON 8 steps（RTX 4060 / 远程 RTX 5090）
       → 生成真实衣层并约束到原人体区域
       → 锚定到捕获姿态，交给实时 Warp
```

这一路线比纯贴图更接近 Kivisense 一类试衣产品的视觉结果，因为它不是把服装
PNG 直接贴在人体上，而是由生成式模型根据人体、服装参考图和替换区域产生衣服
纹理、褶皱和遮挡关系。生成结果随后通过低延迟网格变形持续跟随摄像头中的人物。

必须明确边界：当前 8 步 HTTP 中位数为本机 4.755 秒、5090 隧道 0.961 秒；旧版 20 步完成一次衣层约 12.71–13.52 秒，无法逐帧运行；
旧版实时部分约为 28.89–29.12 FPS（本轮未重测）。系统是“低频 AI 换衣 + 高频动作跟随”，不是
“30 FPS 生成式扩散试衣”。论文、界面和答辩不得混淆两个指标。

RTX 4060 本机可以完成当前推理。远程 GPU 主要作为提速和扩展部署方式，
浏览器仍负责摄像头采集、姿态预处理、结果合成与显示。

## 2. 最小可行版本与当前完成度

### 必须功能

1. 摄像头实时流直接进入试衣循环，不读取上传图片或整段视频文件。
2. 检测人体并自动捕获关键帧，调用 CatVTON 生成真实衣层。
3. 去除生成图中旧衣边缘、白边和背景污染，保留皮肤、头发和手部。
4. 三套服装可现场切换，每套独立生成衣层。
5. 人体慢走、抬手和前后移动时，衣层随姿态和尺度连续变化。
6. 显示 AI 推理耗时、全链路耗时、Warp FPS、姿态/分割耗时和帧抖动。
7. CatVTON 离线或摄像头不可用时，有明确降级路径。
8. 提供可重复的远程 WebSocket RTT 与抖动测量。

### 当前已实现

- CatVTON CUDA 推理服务、模型预加载、状态接口和试衣接口。
- 摄像头人体检测、1 秒稳定判定、自动生成和手动重新生成。
- 衣物语义提取、原始人体差分约束、白边收缩、孔洞填补和 Alpha 收边。
- One Euro 关键点滤波、掩码 EMA、肩肘腕与髋部锚点映射。
- 36×54 三角网格 WebGL Warp、三套服装和性能面板。
- 桌面、移动端、模拟摄像头、后端切换、传输和请求隔离等 9 项 Playwright 测试。
- 一键启动脚本和真实 AI 全链路验收记录。

### 当前不做

- 不逐帧运行扩散模型。
- 不训练新的生成式大模型。
- 不宣称具备真实布料物理、360° 重建或任意服装拓扑。
- 不把 WebSocket ping 当成远程推理端到端延迟。
- 不将非商业 CatVTON 权重用于商业产品。

## 3. 技术路线比较

| 路线 | 视觉真实感 | AI 延迟 | 运动跟随 | 4060 可行性 | 毕设风险 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| 2D 服装贴图 | 低 | 极低 | 差 | 高 | 容易穿帮 | 仅基线 |
| 2.5D 网格 Warp | 中 | 极低 | 中 | 高 | 不是真正的换衣 | 仅实时层 |
| CatVTON 关键帧 + Warp | 需真人复核 | 8 步 HTTP 0.96 / 4.76 秒 | 中 | 已实测 | 生成与实时解耦 | **主路线** |
| 逐帧扩散/DiT | 高 | 秒级到更高 | 易闪烁 | 低 | 帧率和复现风险高 | 不采用 |
| 3D 人体 + 布料仿真 | 中高 | 依赖管线 | 高 | 中 | 建模和工程量大 | 后续研究 |
| 商业试衣 API | 高 | 依赖服务 | 高 | 不依赖本机 | 费用、隐私、可用性 | 备选 |

### 为什么不做逐帧扩散

本机 20 步 CatVTON 的单步去噪约 592 ms，20 步去噪约 11.85 秒。即使把步数
压缩到 4–8 步，仍难以达到摄像头交互帧率，而且低步数会牺牲纹理和边缘质量。
相邻帧独立去噪还会带来闪烁和时序不一致。把扩散限制在关键帧，再用姿态驱动
衣层，是当前本科项目在质量、延迟和可解释性之间更稳妥的组合。

## 4. 开源项目与模型调研

| 项目 | 作用 | 许可/注意 | 本项目用法 |
|---|---|---|---|
| [CatVTON](https://github.com/Zheng-Chong/CatVTON) | 生成式虚拟试衣 | 代码和权重 `CC BY-NC-SA 4.0` | **当前真实衣层生成器** |
| [MediaPipe](https://github.com/google-ai-edge/mediapipe) | 姿态、人体分割和浏览器部署 | Apache-2.0 | **本地实时预处理** |
| [IDM-VTON](https://github.com/yisol/IDM-VTON) | 高保真生成式试衣 | 代码与权重分别核对 | 论文质量对照候选 |
| [OOTDiffusion](https://github.com/levihsu/OOTDiffusion) | 服装条件扩散试衣 | 非商业限制需核对 | 质量/延迟对照候选 |
| [FitDiT](https://github.com/BoyuanJiang/FitDiT) | DiT 高分辨率试衣 | 许可和权重需核对 | 后续高保真候选 |

开源项目选型必须同时检查代码许可、权重许可、输入掩膜要求和显存需求。
“仓库能下载”不等于“模型权重可商用”。当前 CatVTON 仅用于非商业研究和
毕业设计演示，权重不随项目仓库分发。

## 5. 自主改进点

论文不应宣称训练了新的大模型，建议围绕生成结果和实时稳定性提出可测量改进：

1. **关键帧衣层提取**：结合人体语义分割、替换掩膜和原始帧差分，抑制旧衣、
   白边与背景残留。
2. **捕获姿态锚定**：将生成图中的衣层像素从捕获姿态的肩宽、躯干高度和局部
   坐标映射到当前姿态，而不是简单全屏缩放。
3. **分区网格变形**：肩、袖、躯干和衣摆使用不同映射权重与垂坠系数，降低
   大幅动作时的拉伸和脱体。
4. **时序稳定**：One Euro 自适应滤波与人体掩码 EMA，分别抑制关键点跳动和
   边缘闪烁。
5. **降级与测量**：AI 离线、GPU 回退、摄像头失败和远程断线均有清晰状态，
   并区分生成耗时、显示帧率和网络 RTT。

可做消融实验：固定 EMA 对比 One Euro；无掩膜 EMA 对比有掩膜 EMA；
关键帧整体仿射对比锚点网格；20 步对比 8 步的视觉质量和耗时。

## 6. 历史实测：20 步旧版

2026-10-26 最新 8 步对照见 [README](../README.md) 和 [逐次数据](benchmark-20261026.json)。
4060 / 5090 的推理中位数分别为 4.706 / 0.568 秒；HTTP 中位数 4.755 / 0.961 秒。
双方软件版本不同；以下 20 步数据仅为历史记录，不代表当前默认配置。

### 6.1 测试条件

- 设备：RTX 4060 Laptop GPU。
- 系统与浏览器：Windows、Chrome 硬件加速、ANGLE D3D11。
- 摄像头：1280×720，请求 30 FPS，使用固定人物测试视频模拟摄像头流。
- CatVTON：512×768、20 steps、guidance scale 2.5、seed 42。
- 浏览器后端：MediaPipe `GPU delegate`，WebGL renderer 识别为 RTX 4060 Laptop。

### 6.2 AI 与实时链路

| 指标 | 实测 |
|---|---:|
| CatVTON 推理 | 12.71–13.52 s |
| 去噪阶段 | 11.85 s |
| 单步去噪 | 0.592 s |
| HTTP 往返 | 13.02–13.90 s |
| AI 全链路 | 13.90–14.80 s |
| 请求体 | 322.29–322.46 KB |
| 输出尺寸 | 512×768 |
| 推理后 Warp | 28.89–29.12 FPS |
| Pose Lite | 8.77–9.20 ms |
| Selfie Segmenter | 24.72–25.41 ms |
| 帧间隔抖动 | 4.69–5.05 ms |
| 输入替换掩膜 | 202,371–202,425 px |
| 可见衣层 | 195,889–196,482 px |
| 无控制台错误/失败响应 | 是 |

以上范围来自两次完整关键帧换衣验收；最新一次为 AI 13.52 秒、全链路 14.8 秒、
Warp 29.12 FPS。

模型加载指标约 2–3 秒；包含 Python、PyTorch 和模型初始化的服务冷启动实测
17.19 秒。推理峰值显存记录约 2.75 GB。上述耗时是 JS 和 HTTP 观测口径，
不包含显示器扫描输出，也不能直接当作跨主机远程延迟。

### 6.3 网络测量

本机回环 WebSocket 的 24 次 RTT 历史基线为：中位 0.543 ms、P95 0.662 ms、
相邻样本抖动 0.069 ms。该结果只证明诊断接口正常，不代表局域网或公网性能。

远程试衣总延迟应按以下口径测量：

```text
采集 + 预处理 + 编码 + 上行网络 + GPU 排队 + 推理
     + 下行传输 + 解码 + 重投影/Warp + 显示排队
```

远程路径优先使用 WebRTC 视频传输或 GPU 零拷贝链路；不要通过 JSON WebSocket
持续发送全分辨率 JPEG。正式实验至少分别记录 1080p/720p/480p 和
本机回环/局域网/公网三种条件。

## 7. 主要风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| AI 生成非实时 | 8 步 HTTP 约 1–5 秒，首次分割另需初始化 | 关键帧生成；本地 Warp 不断流；界面显示进度 |
| 2D 映射遮挡不足 | 侧身、手挡衣服时穿帮 | 限定正面演示；分区权重；后续引入深度或 3D |
| 衣层分割污染 | 旧衣白边、背景或皮肤被覆盖 | 语义掩膜、人体差分、边缘收缩和孔洞填补 |
| 关键点与掩膜抖动 | 衣摆闪烁、肩线跳动 | One Euro、Mask EMA、置信度门限、保持上一稳定姿态 |
| 远程传输主导延迟 | 网络稍差就卡顿 | WebRTC、降分辨率、丢帧优先、超时回退本地 |
| 权重许可不符 | 商业使用或二次分发风险 | 保持非商业研究；论文和 README 明确许可 |
| 论文表述过度 | 被质疑不是实时生成式试衣 | 明确定义“关键帧生成 + 实时动作跟随” |

## 8. 部署流程

### 本机演示

1. 确认 CatVTON Python 环境和模型目录存在。
2. 在 `virtual_tryon/` 运行 `scripts\start-demo.ps1`。
3. 打开 `http://127.0.0.1:8766/`，确认页面显示 `CATVTON / CUDA READY`。
4. 允许摄像头，人物正面入镜，等待真实衣层生成。
5. 演示抬手、慢走和前后移动，并记录 Warp FPS、抖动和 AI 耗时。

### 远程 GPU

1. 将 CatVTON 服务和模型部署到远程 GPU，保持与本地相同的 `/api/status`、
   `/api/tryon` 契约。
2. 浏览器通过可配置 API 地址连接远程服务；本地继续负责摄像头、姿态和 Warp。
3. 开放端口仅允许演示主机访问，使用 VPN 或受控网络，禁止公开裸接口。
4. 先测模型加载、单帧推理和 HTTP 往返，再接入 WebRTC 视频链路。
5. 设置最大排队长度、超时和断线回退；延迟累积时丢帧而不是排队。

### 性能调优顺序

1. 固定摄像头分辨率和浏览器硬件加速，排除请求帧率漂移。
2. 对 CatVTON 测 8、12、20 步的质量与延迟，选出答辩档位。
3. 尝试 `torch.compile`、Flash Attention 或 xFormers，前后都记录 P50/P95。
4. 对请求图片做有损压缩或 WebP 编码，比较网络耗时和掩膜精度。
5. 将 AI 请求与实时渲染解耦，保持 Warp 主循环不等待推理。

## 9. 开题内容建议

### 题目

《基于关键帧生成式换衣与人体姿态驱动形变的摄像头实时虚拟试衣系统》

### 研究问题

如何在有限显存和摄像头实时流条件下，兼顾生成式试衣的视觉质量、衣服跟随
人体运动的连续性，以及边缘与关键点的时序稳定性？

### 研究内容

1. 摄像头姿态估计、人体分割与关键帧选择。
2. CatVTON 真实衣层生成及语义收边。
3. 捕获姿态到当前姿态的锚点网格映射。
4. One Euro、掩码 EMA 与分区形变的稳定性优化。
5. 本地/远程推理的帧率、延迟、抖动与闪烁评估。

### 预期成果

- 可现场运行的摄像头实时试衣系统与可复现启动脚本。
- 一套 RTX 4060 性能、网络和时序稳定性测试方案。
- 衣层提取、锚点映射和滤波方法的消融实验。
- 本科毕业论文、演示视频、系统说明书和答辩 PPT。

## 10. 论文框架

1. 绪论：虚拟试衣背景、生成式方法、实时系统问题与研究目标。
2. 相关技术：人体姿态、分割、CatVTON、网格 Warp、One Euro 滤波。
3. 系统设计：摄像头前端、关键帧 AI 服务、实时 Warp、远程扩展。
4. 关键方法：衣层提取与收边、捕获姿态锚定、分区网格和时序稳定。
5. 系统实现：CUDA 服务、WebGL、状态管理、降级与遥测。
6. 实验：AI 耗时、Warp 帧率、抖动、闪烁、网络和消融。
7. 总结与展望：步数蒸馏、WebRTC、3D 人体和布料仿真。

## 11. 验收门槛

- 摄像头模式连续运行 10 分钟不崩溃，分辨率至少 640×480。
- 人体稳定入镜后能自动生成真实衣层，换装不需要上传图片或视频文件。
- 生成衣层无明显旧衣白边和背景大块污染。
- AI 后本地 Warp 目标 ≥24 FPS，720p 基线争取 ≥30 FPS。
- 慢走、抬手和前后移动时衣服明显跟随，不出现整件衣服脱体漂移。
- 面板同时显示 AI 推理耗时与实时 FPS，且两者不混用。
- 远程报告包含网络位置、RTT 次数、中位数、P95 和抖动。
- 论文与答辩明确 CatVTON 权重许可和方法边界。
