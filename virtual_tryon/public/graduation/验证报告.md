## 2026-11-03：本机衣柜与完整试衣流程

本轮使用免 GPU 模式及模拟服务测试，不启动远程 GPU，不产生新的真人性能结论。新增真实浏览器流程覆盖：多件服装保存后刷新恢复、选择记忆、收藏筛选、重命名及 HTML 文本转义；临时衣服稍后保存和确认移除；IndexedDB 被禁用时仍可临时试穿且明确报错；偏好重置保留衣柜与收藏；摄像头权限拒绝的操作引导及 320px 对话框无横向溢出。

最终 `npm test` 41 项全部通过（约 1.2 分钟），`npm run build` 通过。旧的“上传替换一件、刷新清空”断言已随多件保存行为更新；上传后切换生成参考、刷新不自动重启生成仍有回归覆盖。记录见 `docs/studio-experience-20261103.json`。

本机衣柜只保存归一化服装 Blob 和必要名称、ID、创建时间，不保存相机或生成画面。上限为 20 件、32 MB；移除仅影响浏览器副本。摄像头启动沿用原采集参数；选择的设备不可用时回退到默认设备。新增引导只在状态变化时更新 DOM，不在帧循环中读写 IndexedDB。

界面目视核查使用桌面 1440×1000、手机 390×844 和 320×780。生成客户端、Worker、模型、分辨率和帧传输协议均未修改；现有最新帧、背压、插值取消、补白映射回归仍需保持通过。该功能扩展阶段未重排Word，后续技术补写已同步，见上节；生成速度、残影和背面一致性不能据界面测试认定已改善。

## 2026-10-28：摄像头有效视野与底部固定条带

用户截图中中央正方形约为 1028×1028，顶边 y≈25；4:3 摄像头应占中央 1028×771，理论实景边界 y≈153.5–924.5，与红框固定条带从 y≈925 开始吻合。静态图不能证明视频冻结，但结合采集代码可确定原来把模型的上下补白也当成了相机内容展示。

本轮不改模型/空间缓存/输入尺寸/编码/采集频率，不重启远程服务。Worker 和主线程后备都返回实际快照的有效区域，随帧 ID 保存，显示同一帧时映射到模型输出。只删除相机视野以外的补白，不裁人物、不抠衣贴回；保持一次 drawImage 和 desynchronized=true。

## 数据解释与未完成项

2026-10-26 历史真人流畅档的采样到绘制 P50 为 490.6 ms、P95 为 844.6 ms、最大为 1037 ms，实际原帧显示约 4.77 FPS。模型推理中位数 122.25 ms，逐帧剩余项中位数约 303.67 ms；剩余项同时包含传输、缓冲和未细分调度，不等于纯网络 RTT，也不能证明更换 H100 就能消除卡顿。

固定样衣 RTV 对照的完整人物/半身输入各 24 个公开抽样帧，流水线 P50 约 109.95/122.91 ms、吞吐约 8.74/8.11 FPS，不含浏览器采集、网络与显示。生成器约 8.6 ms 不是完整流水线速度；抽帧背面结果不是连续真人运动验证，也没有替换生产路径。

当前仍需在 GPU 恢复后，以同人物、同衣图、同动作、同网络进行端到端复测。真实生成卡顿、快速移动时序一致性及胸前图案错误复制到背面，本轮均未宣布解决。原生生成至少 15 FPS、P95 不高于 300 ms 为后续目标，未写作已达成结果。
